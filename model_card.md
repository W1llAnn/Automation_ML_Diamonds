# Model Card: модель предсказания стоимости бриллиантов

Проект: **Automation ML Diamonds** (MLOps-проект, версия 1.0.0).

Model Card составлен по шаблону Google ([Model Cards for Model Reporting](https://doi.org/10.1145/3287560.3287596)) и описывает модель, которая используется в бизнес-процессе оценки бриллиантов (схема процесса — в [Model_BPMN.md](Model_BPMN.md)).

Препроцессинг встроен в пайплайн и одинаков для обучения и инференса:

- числовые признаки (`carat`, `depth`, `table`, `x`, `y`, `z` + производные `volume`, `density`, `depth_to_width`) — медианная импутация + `StandardScaler`;
- категориальные признаки (`cut`, `color`, `clarity`) — импутация по моде + `OneHotEncoder(handle_unknown="ignore")`.

## 2. Intended Use — назначение модели

**Основное назначение.** Оценка справедливой рыночной цены бриллианта (в USD) по его объективным характеристикам. Модель выступает инструментом первичной оценки: по 9 параметрам камня она за доли секунды выдаёт цену, которую эксперт-оценщик далее сверяет с прайс-листами и рыночными аналогами. Проект также демонстрирует полный MLOps-цикл (ETL, обучение, API, тесты, Docker, CI/CD, мониторинг).

**Целевые пользователи.**

- оценщики и продавцы-консультанты ювелирного магазина — быстрая первичная оценка камня;
- покупатели — проверка адекватности запрашиваемой цены;
- разработчики — интеграция через REST API (`POST /predict`).

**Вне области применения (out-of-scope).**

- подтверждение подлинности камня и геммологическая экспертиза (модель не детектор);
- оценка камней, не являющихся бриллиантами (изумруды, сапфиры и т. д.);
- камни с характеристиками вне диапазона обучающих данных (например, `carat > 2.5` для текущей версии);
- юридически значимая оценка для страхования, аукционов, суда — только как вспомогательная рекомендация при обязательном участии человека (human-in-the-loop);
- автоматическое принятие торговых решений без проверки экспертом.

## 3. Factors — факторы

**Анализируемые факторы** — характеристики, по которым цена может систематически различаться:

- `cut` (огранка): Fair, Good, Very Good, Premium, Ideal — 5 категорий;
- `color` (цвет): D…J — 7 категорий (от бесцветного к желтоватому);
- `clarity` (чистота): I1, SI2, SI1, VS2, VS1, VVS2, VVS1, IF — 8 категорий;
- `carat` (вес) и ценовой сегмент камня.

**Факторы, по которым проводилась оценка** (см. раздел 7): `clarity`, `cut` и ценовой сегмент истинной цены камня. Демографические факторы неприменимы: модель работает с характеристиками товара, персональных данных нет.

## 4. Metrics — метрики качества

| Метрика | Значение на тесте | Комментарий |
|---|---|---|
| RMSE | 589.59 USD | Основная метрика; штрафует крупные ошибки сильнее |
| MAE | 483.14 USD | Средняя абсолютная ошибка в долларах — интерпретируется «в лоб» |
| R² | 0.9631 | Доля объяснённой дисперсии цены |
| MAPE | 7.06 % | Средняя относительная ошибка |

Порогов «прошла/не прошла» у метрик нет — чем меньше ошибка, тем лучше. Контроль качества в продакшене устроен через сравнение с baseline, зафиксированным при обучении (`reports/monitoring/baseline.json`, функции `detect_degradation` и `detect_data_drift` в `src/monitoring.py`):

- деградация фиксируется, если RMSE вырос более чем на 15 % относительно baseline или R² упал более чем на 0.10;
- data drift фиксируется, если среднее числового признака сместилось более чем на 25 % относительно baseline-профиля.

## 5. Evaluation Data — данные для оценки

- Hold-out тестовая выборка: **100 строк** (20 % данных после чистки), `data/processed/test.csv`.
- Способ формирования: `train_test_split(test_size=0.2, random_state=42)` — фиксированный, оценка воспроизводима.
- Текущие метрики посчитаны на детерминированном сэмпл-датасете проекта (500 строк). При размещении полного Kaggle CSV (53 940 строк) в `data/raw/diamonds.csv` пайплайн автоматически переобучится и переоценится на нём — значения метрик изменятся.
- Preprocessing тестовой выборки — тот же pipeline, что и на обучении (скейлер и импьютеры обучаются только на train).

## 6. Training Data — обучающие данные

| Параметр | Значение |
|---|---|
| Источник | Kaggle Diamonds Dataset; при отсутствии CSV — детерминированный сэмпл, сгенерированный кодом проекта |
| Объём текущей версии | 400 строк train (80 %) / 100 строк test (20 %) |
| Целевая переменная | `price`, USD |

Подготовка данных (`src/data_processing.py`):

1. **Валидация** — наличие обязательных колонок, непустой датасет, числовые типы у числовых признаков.
2. **Чистка** — удаление дубликатов и строк с пропусками; отбраковка физически некорректных значений (`carat`, `price`, `x`, `y`, `z`, `depth`, `table` ≤ 0; `depth` вне [40, 80]; `table` вне [40, 90]).
3. **Feature engineering** — `volume = x·y·z`, `density = carat / (volume + 0.001)`, `depth_to_width = depth / (x + 0.001)`.
4. **Разбиение** — 80/20 с `random_state=42`.

Диапазоны признаков текущей обучающей выборки (baseline-профиль): `carat` 0.21–2.49, `x` 4.41–9.64, `y` 4.37–9.39, `z` 2.47–5.70, `depth` 55.4–67.0, `table` 50.4–65.2.

## 7. Quantitative Analyses — количественный анализ

**Общие метрики на hold-out тесте (n = 100):** RMSE 589.59 USD; MAE 483.14 USD; R² 0.9631; MAPE 7.06 %.

Разбивка по группам посчитана на той же тестовой выборке; она небольшая, поэтому значения по редким категориям следует воспринимать как ориентировочные.

**По чистоте камня (`clarity`):**

| Категория | n | MAE, USD | MAPE, % |
|---|---|---|---|
| SI1 | 13 | 328.3 | 4.5 |
| VS2 | 13 | 304.8 | 4.9 |
| IF | 13 | 541.8 | 5.9 |
| SI2 | 15 | 362.8 | 6.6 |
| VS1 | 6 | 548.6 | 6.8 |
| VVS2 | 12 | 610.1 | 7.5 |
| VVS1 | 11 | 764.0 | 8.7 |
| I1 | 17 | 504.8 | 10.8 |

**По огранке (`cut`):**

| Категория | n | MAE, USD | MAPE, % |
|---|---|---|---|
| Very Good | 22 | 428.3 | 5.6 |
| Premium | 29 | 449.6 | 6.9 |
| Ideal | 26 | 547.2 | 7.1 |
| Good | 17 | 494.4 | 7.4 |
| Fair | 6 | 536.7 | 11.6 |

**По ценовому сегменту истинной цены:**

| Сегмент | n | MAE, USD | MAPE, % |
|---|---|---|---|
| 1000–3000 USD | 3 | 532.5 | 20.2 |
| 3000–6000 USD | 31 | 372.1 | 8.4 |
| > 6000 USD | 66 | 533.1 | 5.8 |

**Выводы из анализа.**

- Абсолютная ошибка (MAE ≈ 300–760 USD) почти не зависит от цены камня, поэтому **относительная ошибка на дешёвых камнях заметно выше** (до ~20 % в сегменте 1000–3000 USD против ~6 % на камнях дороже 6000 USD).
- Хуже всего модель предсказывает редкие и дорогие категории (`VVS1`, `VVS2`) и крайние категории огранки (`Fair`, `I1`) — таких примеров в данных меньше всего.
- По feature importance основной вклад дают `carat`, `volume` и размерные признаки (`x`, `y`, `z`) — график в `reports/figures/feature_importance.png`.

## 8. Ethical Considerations — этические аспекты

- **Персональных данных нет**: модель работает исключительно с характеристиками товара.
- **Риск чрезмерного доверия**: предсказание — это статистическая оценка по историческим ценам, а не гарантия стоимости. Использовать её как единственное основание для сделки нельзя; в процессе оценки всегда участвует человек (см. [Model_BPMN.md](Model_BPMN.md)).
- **Систематические смещения**: для редких категорий (`VVS`, `Fair`) ошибка выше — при использовании модели в этих сегментах цена может систематически отклоняться от рынка. Это явно задокументировано в разделе 7, чтобы пользователи понимали границы применимости.
- **Актуальность данных**: модель отражает рынок на момент сбора датасета; изменение конъюнктуры без переобучения приведёт к смещению оценок (частично компенсируется мониторингом дрейфа).

## 9. Caveats and Recommendations — ограничения и рекомендации

**Ограничения текущей версии.**

1. Метрики посчитаны на детерминированном сэмпле (500 строк), а не на полном Kaggle-датасете — это учебный компромисс ради воспроизводимого запуска.
2. Экстраполяция за пределы обучающих диапазонов (например, `carat > 2.5`) не поддерживается: API проверяет только положительность значений (`Field(gt=0)`), но не принадлежность обучающему диапазону.
3. `OneHotEncoder(handle_unknown="ignore")` молча зануляет незнакомые категории — опечатка в `cut`/`color`/`clarity` не вызовет ошибку, а исказит предсказание.
4. Модель выдаёт точечную оценку без интервала неопределённости.
5. Дешёвые камни: относительная ошибка до ~20 % (см. раздел 7).

**Рекомендации.**

- Переобучить модель на полном Kaggle-датасете и обновить эту карточку и baseline.
- Перейти на логарифм таргета или взвешенную функцию потерь, чтобы выровнять относительную ошибку между дешёвыми и дорогими камнями.
- Добавить в API валидацию диапазонов признаков и предупреждение, когда запрос выходит за пределы обучающих данных.
- Возвращать интервал предсказания (например, квантильный лес) вместе с точечной оценкой.
- Продолжать регулярный контроль через `detect_data_drift` / `detect_degradation` и переобучаться при срабатывании порогов.
